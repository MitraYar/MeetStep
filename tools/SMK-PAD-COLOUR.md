# Простой тестер цвета SMK 37 Pro — 0.3.1 (заморожен)

Режим «Максимум» проверен пользователем и работает стабильно. Новых билдов
утилиты не планируется. Поле «яркости» в интерфейсе фактически включает/выключает
LED; 80% и 100% не дают разных уровней яркости. Далее сохранена инструкция
к последнему выпуску; актуальный протокол — [LED.md](../docs/protocol/LED.md).

Запустите MeetStep-SMK-Pad-Colour.exe из распакованного архива.
Установка Python для EXE не нужна.

1. В MidiSuite выберите первый пресет (индекс 0), затем закройте MidiSuite.
   Тестер использует адреса этого пресета, как подтверждённый pad-one билд.
2. Выберите MIDI-вход и MIDI-выход SMK. Начните с первой пары SMK-37 Pro Midi,
   которая работала в pad-one тестере. Номера в именах портов могут меняться.
3. Для первого теста оставьте пэд 1 и цвет #4CE437: первые три сообщения совпадают с рабочим захватом;
   четвёртое задаёт яркость 255. Нажмите «Отправить цвет».
4. В логе должны появиться открытие обоих портов, четыре строки TX и четыре RX ACK.
   После подтверждений проверьте светодиод контроллера.
5. Выберите другой пэд, задайте RGB слайдерами или кнопкой палитры и отправьте.

Цвет отправляется только кнопкой. При ошибке нет автоматических повторов;
«Стоп» прекращает оставшуюся отправку. Уже отправленные компоненты цвета могут
сохраниться, поэтому при остановке цвет бывает промежуточным. Закрытие утилиты
не восстанавливает прежние цвета. Кнопка «Копировать лог» копирует точные TX/RX.
Программа не вызывает Save to device, не переключает пресет.

Доступны 32 RGB-ячейки, подтверждённые сравнением чёрного/белого пресетов.
Для банка 1 порядок соответствует известной карте. У банка 2 физическое
соответствие номерам 17–32 ещё проверяется: наблюдайте, какой пэд изменился.
ACK подтверждает приём команды, но не заменяет наблюдение за светодиодом.

Основа MIDI — принятый рабочий билд 2770a7a: Mido input callback, короткие
однобайтовые записи и ACK. Режим определяет паузу и размер записи, ожидание ACK —
до 2 секунд. Бывшие LED/RGB-транспорты не используются. Большие чтения пресета,
set_buffer_size, автоотправка слайдеров и случайные цвета не входят в этот
простой диагностический этап.

Сборка: GitHub Actions → SMK Simple Pad Colour Windows →
MeetStep-SMK-Pad-Colour-0.3.1-Windows-x64. Workflow проверяет сообщения по
захватам, Mido-адаптер с имитацией RtMidi, GUI и запуск упакованного EXE.
Тесты не заменяют аппаратную проверку на SMK.

Для запуска исходников: Python 3.12, mido==1.3.3, python-rtmidi==1.5.8;
команда `python tools/smk_pad_colour.py` из корня репозитория.

## Яркость и все пэды

Бегунок задаёт яркость 0–255 для выбранного пэда; по умолчанию 255.
«Все пэды» применяет выбранный RGB и значение бегунка ко всем 32 ячейкам.
«Чередование яркости» доступно вместе со «Все пэды»: нечётные номера получают
255, чётные — процент от 255, заданный тем же бегунком. Бегунок переключается
на шкалу 0–100%; начальное значение 80% соответствует 204. Например, 40% даёт
255/102/255/102. При выключении галочки восстанавливается прежнее значение
бегунка 0–255. Значения обоих режимов запоминаются до закрытия программы.
Это чередование между пэдами в одном проходе, а не непрерывное мигание.

Групповая отправка — 128 коротких сообщений (RGB + яркость каждому), один
раз открываются MIDI-порты. В режиме «Максимум» вместо 128 отправляются 32
сообщения, каждое содержит RGB + яркость одного пэда.
После каждого сообщения ожидается ACK; ошибка или Стоп прекращают всю
оставшуюся отправку. Уже применённые цвета/яркости автоматически не откатываются.
Адреса яркости подтверждены новым захватом `all white to lights off.pcapng`.

## Скорость и замер

- «Быстро»: отдельные записи, без искусственных пауз. По умолчанию.
- «Максимум»: RGB + яркость одним четырёхбайтовым блоком на пэд, без пауз.
  Экспериментальный режим: формат блоков подтверждён захватом, но приём
  именно четырёхбайтовых записей нужно проверить на устройстве.
- «Щадящий»: отдельные записи с паузой 5 мс после ACK.

Все режимы ждут ACK после каждого сообщения. Нулевая пауза не означает
отправку без подтверждений. Ошибка или таймаут прекращают проход без
автоматического повтора/смены режима.

Итог в GUI показывает ACK/план и время от первой отправки до последнего ACK
в миллисекундах, без времени открытия/закрытия портов и отрисовки подробного
лога. При ошибке в логе указан прерванный проход, число TX/ACK и время до
остановки. Подробные TX/RX выводятся после замера, чтобы не тормозить обмен.
В логе также есть среднее и максимальное время ответа ACK.

Для сравнения включите «Все пэды», меняйте цвет между проходами и попробуйте
каждый режим. Сопоставляйте итоговое время, количество ACK и физический
результат на пэдах. Цель <100 мс требует измерения на реальном контроллере.

## Размер окна

Начальный размер учитывает рабочую область Windows и панель задач (в том
числе экран 1600×900). Настройки прокручиваются полосой справа, колесом мыши
или Page Up/Page Down. Кнопки отправки, Стоп и статус закреплены снизу.
Колесо над слайдером прокручивает форму без изменения значения. Лог имеет
собственную прокрутку. Окно можно уменьшать и растягивать.
