# Яркость всех 32 пэдов: подтверждение захватом

Источник: `all white to lights off.pcapng`, 244112 байт.
SHA256: `599d052459ea2b846785f4dcace3ccae315b9de9975d8c7bd740e6fe2009e083`.

2014 USBPcap-пакетов, 190 полных SysEx. Проверены длины, контрольные суммы
и побайтное повторное кодирование всех сообщений; ошибок и обрывов нет.
Шина 1, устройство 16, OUT 04 / IN 84, MIDI cable 0.

Два образа по 18915 байт переданы в регион 5, адреса от 0. Каждый: 18 блоков
по 1024 байта и 483 байта, каждый подтверждён ACK. Записи в кадрах 29–508
и 1026–1505. Каждый образ затем прочитан полностью (18 × 1009 + 753 байта),
все позиции покрыты ровно один раз, оба чтения побайтно совпадают с записью.
Во всех 19 ответах статуса первый байт 00: пресет с индексом 0.

**Между образами меняется ровно 32 байта, все FF → 00. RGB у всех 32
остаётся FFFFFF.** Хотя пользователь описал изменение цвета вместе с
яркостью, именно эти два переданных образа различаются только яркостью.
Это снимает прежнюю неоднозначность байта сразу после RGB для второй банки:
в новом опыте все 32 таких поля меняются согласованно с яркостью.

Адрес: `0x11E + (номер записи − 1) × 0x4A`. Номера — порядок записей;
физическое соответствие второй банки по-прежнему проверяется пользователем.

Новая утилита использует тот же короткий CMD 22, region 05, length 1,
как для RGB; после трёх цветовых байтов отправляется четвёртый — яркость.
Захват подтверждает поля в полном пресете; короткие записи яркости по всем
32 адресам ещё требуют аппаратной проверки. Ранние однобайтовые записи
яркости пэдов 1–5 подтверждены прежним захватом.

«Все пэды» — один последовательный проход 1–32, 128 коротких сообщений,
каждое с ACK и паузой 100 мс между сообщениями. Это групповая операция в GUI,
а не одновременный USB-пакет: порядка 13 секунд при нормальных ответах.
При ошибке/Стоп проход прекращается; уже применённые значения сохраняются.
Чередование — по номерам ячеек, не мигание во времени. Полная яркость 255,
уменьшенная задаётся бегунком как процент; начальные 80% дают 204. Без
чередования бегунок 0–255 регулирует выбранный пэд или все сразу.
